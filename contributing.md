# Contribution Guidelines

1. **Search the list and open pull requests first.** Yours may be a duplicate.
2. **Use the entry format.** One line per entry, markers first:

   ```markdown
   - 🔁 📄 💻 [Name](https://doi.org/...) - One sentence describing what the system does. ([code](https://github.com/...))
   ```

3. **Meet the evidence bar.** A new Agents entry needs a paper, preprint or repository showing the system acting on physical hardware. Press coverage alone qualifies only for Organizations.
4. **Unverified leads go to [backlog.md](backlog.md), not into the readme.** If you cannot trace an identifier to its primary source, it is a lead. This is the most important norm in the project.
5. **Assign markers from the [Emoji Key](readme.md#emoji-key).** 🔁 means the agent selects the next round of experiments across multiple rounds, without a human deciding between rounds. If the paper is ambiguous about whether the agent chose subsequent rounds itself, omit 🔁.
6. **Keep descriptions plain.** One sentence, roughly 200 characters or fewer, starting with a capital and ending with a dot. Say what the system does, with at most one number. No marketing language.
7. **Self-promotion is welcome.** Disclose it in the pull request.
8. **Classification disputes are a legitimate issue type.** Whether something earns 🔁 or ⚠️ is a judgment call, and the list gets better when those are argued in public. Maintainers reply with a rationale rather than making silent edits.
9. **Open a pull request.** Fork, create a branch, add one entry per pull request where practical, and say why the entry is worth including.
